# Public web startup and subscription release

The subscription customer-settings release exposed an existing public startup
budget failure. The release remains gated on the configured mobile Lighthouse
limits: LCP at most 2500ms and CLS at most 0.1. Bundle reduction alone is not a pass.

## Verified causes and changes

- Settings, authentication, Studio setup and profile routes were eager imports.
  They now use the existing route Suspense/error handling.
- Reading the subscription acceptance version imported all nine policy bodies.
  The legal generator now emits a small version module. Policy contents,
  acceptance version and native documents remain identical.
- The HTML preload filter expected `/assets/`, but Vite supplies `assets/`.
  It now handles both forms. The regression guard checks the built HTML contains
  exactly the three core vendor preloads and no unopened feature/admin chunks.
- The initial page's lazy route otherwise starts downloading after app boot.
  The build now creates a small external bootstrap from Vite's actual manifest,
  selecting only the current public route and its static dependencies. CSS uses
  style preload hints; JS uses module preload hints. Dynamic interactions stay
  outside the preload graph. Dev uses an intentional empty bootstrap without
  production hashes. Production builds fail for missing entries/assets and
  remove the internal build manifest after generating the public URL list.
- Closed drawers and the design viewer imported and ran their component trees.
  Their first mount is deferred; subsequent mounts remain alive for the original
  state/exit lifecycle. The design viewer's Back handler is armed before its
  download starts. A test cancels a slow load with Back, resolves it, and verifies
  it cannot reopen the viewer or create an extra history entry.
- All three comment composers now load their shared emoji implementation on
  demand, preserving each composer's theme, dimensions and selection behavior.
- Route warm-up waits until page load plus 5 seconds, runs one import per idle
  slot, respects Data Saver/2G, and cancels pending callbacks on unmount.
- The boot mask uses the existing canonical 192px loader artwork (43822bytes)
  instead of the 512px mark (220118bytes). No new artwork or lossy compression.
- The wordmark now offers 160/320/720px responsive candidates. Small headers can
  fetch the 25709-byte candidate instead of the331673-byte full file, using
  browser-selected density and rendered width. PNG encoding stays lossless;
  candidates are resized from the original master and the full artwork remains
  available. This does not establish a percentage of original image quality.
- React vendor classification now matches complete package paths, preventing
  `@sentry/react` from being mistaken for `react`. The absent-DSN guard is
  statically removable. Configured tracing, tag capture and PII settings retain
  their existing behavior and have dedicated configuration tests.
- Playfair Display and Plus Jakarta Sans are served by WIEZ. All 28 font-face
  definitions, eight unmodified WOFF2 payloads, original weights, Unicode ranges,
  swap behavior and licenses are retained. The main Latin text font is preloaded;
  extended Latin (including NGN and accented names) is loaded when required.

## Font maintenance

Normal builds use committed files and require no font-service connection.
Run `node scripts/vendor-web-fonts.mjs` explicitly to refresh the official font
assets. Review the source manifest, SHA256 hashes, licensing, weights and Unicode
ranges before committing. The script refreshes the body-font preload reference.
The font test verifies payload hashes, WOFF2 signatures, licenses and all 28 faces.
Content-hashed WOFF2 filenames can be cached immutably; metadata is revalidated.

The loading method follows [Chrome's font-loading guidance](https://web.dev/articles/optimize-webfont-loading).
Font licenses are distributed under `public/fonts/wiez-web/` with the Playfair
FONTLOG.
